# Sandbox Projects

## Purpose

Create explicitly requested experimental projects with clear ownership under
the sandbox hierarchy, without pretending they are corporate spokes or clusters.

## Accelerator Contract

Native sandboxes is a list of project_name, project_owner_email and optional
owner_emails. The root creates the sandbox module only for a nonempty list and
uses governance's sandbox folder and a derived naming prefix. Sandbox creation
does not enable the landing-zone project's network/DNS/Secrets Manager options.
The common document maintains stable sandbox identities during editing/import.

## Dependencies

Governance/identity foundations and provider authorization. An optional external
application workflow is separate from this native list; a knowledge dependency
is not a request to create an SNA or firewall for sandbox entries.

## Dialogue

Ask who owns each sandbox, purpose and required isolation. Treat lifecycle,
budget controls and expiry as separate explicit requirements, not features
automatically implemented by a sandbox label. Do not invent 100 sandboxes from
an organization's eventual project-count estimate.

## Examples

Synthetic opt-out: sandboxes = []. A new sandbox needs confirmed project_name
and project_owner_email; optional additional owners require explicit choice.
This list fragment is not permission to remove existing deployed projects.

## Limits

Native Editor proposals support reviewed sandbox configuration; platform
templates are not deployed instances. No automatic expiry,
cost cap, corporate routing or application publication is promised by this
native module. Deleting configuration entries needs a separate reviewed plan
and authorization; it is not conversational cleanup.

## Credentials

Provider/Resource Manager permissions stay external; owner email is not a
credential or a grant receipt. Never request passwords, role secrets or tokens.

## Sources

Root sandbox wiring, module variables and common document identities are
manifest authorities. Re-review list/identity/native export changes before
regeneration; provider quota and lifecycle behavior need separate qualification.
